## Deferred verification — run this on `dev-luminous-update`

This rename (Tasks 1–5) was built in a git worktree, **not** the mutagen-synced theme
directory. Nothing in it reached the dev site, so none of the following has been visually
confirmed. All of it is deferred to whoever runs the integration pass on the
`dev-luminous-update` branch, where the pending PRs land together for testing. Work through
this list there; it isn't safe to sign off on the rename without it.

1. **Rebuild `assets/built/` on the CT first.** `assets/built/screen.css` is what Ghost
   serves, and it's generated by gulp running on the container — this PR only changed the
   `assets/css/screen.css` source. **Until that rebuild happens, the Luminous tagline will
   render unstyled**: it will inherit the base `.wc-hero-tagline` rule (italic, 2.3rem)
   instead of the intended `.wc-hero-tagline--luminous` rule (roman, 1.8rem). That's a
   build-ordering fact, not a defect — don't file it as a bug if seen before a rebuild.
2. Confirm `{{#get "tags" filter="slug:luminous" limit="1"}}` actually resolves a populated
   description — i.e. the Luminous show blurb renders and isn't empty.
3. Confirm both hero taglines render, with the `<em>` intact around *To The Best Of Our
   Knowledge* on the WC homepage.
4. Confirm the WC homepage is **visually unchanged** — Task 2 was a pure refactor (moving the
   tagline into a custom setting) and any visible delta there is a regression.
5. Confirm the en dash in "Wisconsin–Madison" survives rendering (not mangled into an HTML
   entity or collapsed to a plain hyphen).
6. Tune `.wc-hero-tagline--luminous`'s `max-width` (currently `44ch`) and `font-size`
   (currently `1.8rem`) against the real render — both were chosen without being able to see
   the page, and the wrap point is unverified.
7. Check tagline legibility where the cream wavy background pattern runs bright behind it.
8. Empty-field check: clear each tagline custom setting in Ghost Admin, confirm the slot
   collapses cleanly with no empty `<p>` or leftover gap, then restore the value.
9. Run the `wc-theme-qa` cross-brand harness, including the §A "WC is a visual no-op"
   invariant.

Also note: adding a custom setting requires a Ghost restart
(`sudo systemctl restart ghost-dev`) to be picked up — a browser refresh alone will not
surface the new `luminous_hero_tagline` field in Ghost Admin.
